# P02B-03 · Host debugging and remote diagnostics — Scientific and technical companion

**Purpose:** distinguish justified inference, engineering selection and future biological research for [design P02B-03](P02B-03_Host_Debug_and_Remote_Diagnostics_Design.md).

## Measurable question

Can the declared subsystem perform its specific function and provide independently interpretable data **without** relying on hidden information, unchecked physical changes or overstated biological claims?

**Candidate mechanism or limitation:** A software status indicator is not a calibrated physical measurement. Dashboard success does not establish biological health or learning.

## Alternative explanations and negative cases

expired packet; duplicated sequence; Bluetooth session spoof; stale state displayed as current; telemetry flood; untrusted client action. Model nonacquisition, access impairment, instrumentation failure and physiological support changes as distinct candidate explanations when relevant.

## Evidence program

1. Verify source and unit validity with independent reference data.
2. Freeze relevant analysis/decoder configurations before held-out evaluation.
3. Compare against a simple conventional/digital-only baseline with matched information.
4. Introduce one declared change and measure the entire affected outcome vector, including resource and protected-task cost.
5. Report negative or unresolved outcomes without promoting a hypothesis to finding.

**Concrete acceptance checks:** out-of-order frame rejection; invalid-auth denial; offline BLE loss; restart/no replay; monotonic audit chain.

## Biological and hardware qualification

Wireless link is never on the essential-care or stimulation permit path. Nothing in this document substitutes for manufacturer approval, a controlled laboratory preparation, a tissue handling SOP, institutional oversight or independent physical safety review.
