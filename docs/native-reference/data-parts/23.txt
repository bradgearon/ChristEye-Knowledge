Local session transfer\nuses an explicit offline import while the relevant store can be exclusively\nowned; network <code>PUBLISH<\/code> supplies live mesh ingress.<\/p>\n<p>The host admits at most eight connections and sixteen queued owner jobs. Each\nenrolled principal has one current application connection. Reading a socket\nand waiting for the owner are separate operations: transport deadlines do not\nturn filesystem publication into a hard real-time operation. Trusted service\nextensions observe authorization, ingress, replay and artifact events without\nreentering the owner or blocking it.<\/p>\n<p>Implementation:\n<a href=\"https://github.com/bradgearon/ChristEye-Knowledge/blob/6175585acf9522582b92e9546b71319443396b39/native/include/anaiero/infrastructure/native_mesh_host.hpp\">host<\/a>,\n<a href=\"https://github.com/bradgearon/ChristEye-Knowledge/blob/6175585acf9522582b92e9546b71319443396b39/native/include/anaiero/application/native_mesh_application.hpp\">application<\/a>,\n<a href=\"https://github.com/bradgearon/ChristEye-Knowledge/blob/6175585acf9522582b92e9546b71319443396b39/native/include/anaiero/contracts/mesh_host.hpp\">host contracts<\/a>.<\/p>\n<h2>Transport identity and enrollment<\/h2>\n<p>The transport uses TLS 1.3 only, mutual certificate authentication and the ALPN\nidentifier <code>anaiero-mesh/1<\/code>. The native client requires both successful CA-chain\nverification and an exact SHA-256 pin of the server certificate. The server\nrequires a verified client certificate, then asks enrollment policy whether\nthat certificate belongs to an authorized principal. Every operation checks the current enrolled generation, certificate,\nexpiry, revocation and capability. <code>NEXT<\/code> and <code>ACK<\/code> resolve their persisted\nsubscription scope and authorize it again. Artifact chunks are authorized\nagain even after their description was previously read.<\/p>\n<p>Policy updates use an expected durable revision. Changed peer records advance\ntheir generation; removed authority is represented by a revoked tombstone.\nSuccessful replacement/reload invalidates existing verified-session handles.\nAn uncertain policy write closes authority until a successful reload establishes\nthe committed policy. Certificate/enrollment expiry is checked per request;\nthe service keeps a nondecreasing view of wall time during its lifetime.<\/p>\n<p>Only the same-user local administration endpoint accepts <code>IMPORT<\/code>, <code>REVOKE<\/code>\nand <code>RELOAD<\/code>. Revocation takes effect at the next serialized request;\nan operation already authorized and committed before revocation retains its\nhistorical receipt.<\/p>\n<p>The local configuration and policy files use canonical sealed formats\n<code>CEVMESH/1<\/code> and <code>CEVMESHPEERS/1<\/code>. Their SHA-256 seals detect altered bytes; they\nare not remote signatures. Credential paths are local files supplied by the\noperator. The first release uses operator-managed trust and certificate\nrotation; it does not implement a public enrollment authority, automated\ncertificate issuance, online revocation fetching or dynamic service discovery.<\/p>\n<p>Implementation:\n<a href=\"https://github.com/bradgearon/ChristEye-Knowledge/blob/6175585acf9522582b92e9546b71319443396b39/native/include/anaiero/infrastructure/native_tls.hpp\">TLS adapter<\/a>,\n<a href=\"https://github.com/bradgearon/ChristEye-Knowledge/blob/6175585acf9522582b92e9546b71319443396b39/native/include/anaiero/contracts/mesh_identity.hpp\">identity records<\/a>,\n<a href=\"https://github.com/bradgearon/ChristEye-Knowledge/blob/6175585acf9522582b92e9546b71319443396b39/native/include/anaiero/services/mesh_authorization_service.hpp\">authorization service<\/a>,\n<a href=\"https://github.com/bradgearon/ChristEye-Knowledge/blob/6175585acf9522582b92e9546b71319443396b39/native/include/anaiero/infrastructure/mesh_configuration.hpp\">configuration codec<\/a>.<\/p>\n<h2>Durable ingress and provenance<\/h2>\n<p>An authenticated publication follows this order:<\/p>\n<ol>\n<li>Check the peer's exact source/epoch/clock/colony grant, canonical observation\nshape, source ordering and projection capacity.<\/li>\n<li>Commit an immutable ingress receipt in the metadata Registry.<\/li>\n<li>Commit the canonical observation in the evidence Registry.<\/li>\n<li>Advance the live Projector and its checkpoint mirror.<\/li>\n<li>Return <code>PERSISTED<\/code> with the local evidence cursor and receipt digest.<\/li>\n<\/ol>\n<p>The receipt records the principal, certificate, enrollment generation, policy\nrevision, local receipt time, source identity, source sequence and exact payload\ndigest. Its ingress kind distinguishes a mutual-TLS arrival from an explicitly\nauthorized local import. Retrying identical bytes reuses the first receipt,\nincluding its original certificate and receipt time. An old duplicate does\nnot rewrite provenance after certificate rotation.<\/p>\n<p>A source/epoch has one durable principal owner and one clock/colony binding.\nCompeting publication grants are rejected. Revoking a principal does not allow\na replacement principal to continue its existing source epoch; the replacement\nmust begin a new epoch. A different colony also requires a different source\nor epoch. This complete-stream rule lets an exact scoped subscription preserve\nthe strict per-source observation sequence.<\/p>\n<p>The current projection additionally keeps a source ID's clock binding across\nits retained epochs. Changing that clock requires a new source ID. Native\nengine exports already provide stable source clocks and use one colony per\nengine stream.<\/p>\n<p>The adapter accepts exact previously committed observations, including old\nduplicates, and rejects changed bytes under an existing sequence, gaps, changed\nclock/colony/origin and backward acquired time. A failed persistence or\nprojection boundary stops ingress until recovery. On restart,\n<code>MeshRecoveryService<\/code> verifies the exact canonical ingress receipt and payload\ndigest for each checkpoint source tip before restoring that checkpoint. It\nperforms the same check on every committed tail observation before projection.\nMissing or mismatched receipts stop recovery, including when evidence survives\nbut the corresponding metadata has been restored to an older state. The\ncheckpoint mirror advances only after durable evidence publication.<\/p>\n<p>Startup checks the retained checkpoint tips and active tail, rather than\nreplaying every archived observation. The offline <code>maintain<\/code> command performs\nthe full evidence-to-receipt audit before checkpoint/archive maintenance and\nunreferenced-object collection. Receipt lookups use bounded memory but may\nscan historical metadata; this release does not promise constant startup or\nmaintenance time independent of retained history.<\/p>\n<p>An ingress receipt establishes what this node durably received through a\nspecified admission path. It is not a transferable signature from an original\nauthor, biological calibration, or proof that a measured value is true.\nObservation origin and model/timebase semantics remain explicit. This first\nnetwork publication path accepts simulated observations; it does not grant\nphysical actuation, scientific solver launch or remote experiment execution.<\/p>\n<p>Implementation:\n<a href=\"https://github.com/bradgearon/ChristEye-Knowledge/blob/6175585acf9522582b92e9546b71319443396b39/native/include/anaiero/contracts/mesh_ingress.hpp\">ingress contract<\/a>,\n<a href=\"https://github.com/bradgearon/ChristEye-Knowledge/blob/6175585acf9522582b92e9546b71319443396b39/native/include/anaiero/services/mesh_ingress_service.hpp\">ingress service<\/a>,\n<a href=\"https://github.com/bradgearon/ChristEye-Knowledge/blob/6175585acf9522582b92e9546b71319443396b39/native/include/anaiero/infrastructure/mesh_ingress_store.hpp\">receipt store<\/a>,\n<a href=\"https://github.com/bradgearon/ChristEye-Knowledge/blob/6175585acf9522582b92e9546b71319443396b39/native/include/anaiero/services/mesh_recovery_service.hpp\">recovery service<\/a>,\n<a href=\"https://github.com/bradgearon/ChristEye-Knowledge/blob/6175585acf9522582b92e9546b71319443396b39/native/include/anaiero/infrastructure/windstore_epoch_observation_journal.hpp\">epoch journal<\/a>.<\/p>\n<h2>Subscription, replay and reconnect<\/h2>\n<p>A subscription identity binds a principal, caller-chosen bounded ID and an\nimmutable exact scope. Reusing that principal/ID with a different scope fails.\nCertificate rotation keeps the durable subscription identity while a new\nverified connection reopens its volatile state.<\/p>\n<p><code>SUBSCRIBE<\/code> includes the receiver's durable global sequence/hash. The server\nchecks that exact tip against its retained history before offering an earlier\nunacknowledged page. The client also rejects a server ACK ahead of its own\ndurability, or an equal-sequence hash disagreement. Restoring a sender or\nreceiver from an incompatible backup therefore requires explicit recovery;\nreconnect cannot silently replace already accepted history.<\/p>\n<p>Each <code>NEXT<\/code> offers at most sixteen matching observations while considering at\nmost sixty-four global event records against the subscription. Other scopes'\npayloads are not returned.\nThe response includes an <code>after<\/code> cursor and a terminal global sequence/hash.\nThe terminal cursor accounts for examined records outside the subscribed\nscope without disclosing their payloads. It is an authenticated server-issued\noffer, not a standalone cryptographic proof for third parties.<\/p>\n<p>One outstanding page per subscription provides backpressure. Repeating <code>NEXT<\/code>\nbefore acknowledgement returns the same offer. <code>ACK<\/code> accepts exactly that\noffer's terminal sequence/hash, or an identical already committed ACK. It\nrejects skipped, forged, conflicting and regressing boundaries. The server\npersists the ACK before reporting success. A newly registered zero cursor is\ndurable, so an unacknowledged reader participates in retention immediately.<\/p>\n<p>The receiver durably advances its remote cursor after each accepted observation,\nfollowing its own receipt/evidence/projection boundary. It then records the\npage's terminal cursor before acknowledging the page. A crash between those\nsteps can replay the unacknowledged page; exact committed duplicates are\naccepted without extra projection revisions. Cursor identity includes the\nremote principal, subscription and exact scope, with the current generation\nretained in the local receipt file.<\/p>\n<p>Reconnect and user-requested synchronization perform bounded reconciliation,\nwith at most 4,096 pages per invocation and durable progress retained if that\nbudget is exhausted.\nThere is no periodic database polling or autonomous push daemon in this\nincrement. A disconnect drops only volatile offers; durable ACK and receive\ncursors remain. An empty caught-up page is not cached permanently, allowing a\nlater explicit request to observe newly committed evidence.<\/p>\n<p>The existing Registry callback subscription API is not exposed over the\nnetwork. Mesh paging uses <code>read_event_page<\/code>: logarithmic segment-metadata\nlookup, bounded segment/event reading, and separately verified payload fetches.\nSegment integrity validation can read the complete bounded segment containing\nthe selected records; the sixty-four-record budget describes subscription\nfiltering and cursor advancement, not an exact count of all decoded metadata.\nSlow readers retain unacknowledged hot segments. Once archived, retained cold\nhistory remains available to reconnecting and newly registered readers.<\/p>\n<p>Implementation:\n<a href=\"https://github.com/bradgearon/ChristEye-Knowledge/blob/6175585acf9522582b92e9546b71319443396b39/native/include/anaiero/contracts/mesh_replay.hpp\">replay contract<\/a>,\n<a href=\"https://github.com/bradgearon/ChristEye-Knowledge/blob/6175585acf9522582b92e9546b71319443396b39/native/include/anaiero/services/mesh_replay_service.hpp\">replay service<\/a>,\n<a href=\"https://github.com/bradgearon/ChristEye-Knowledge/blob/6175585acf9522582b92e9546b71319443396b39/native/include/anaiero/infrastructure/windstore_mesh_replay.hpp\">store adapter<\/a>.<\/p>\n<h2>Immutable artifacts<\/h2>\n<p>The enrollment policy grants exact artifact root digests.
