**Standalone StarChip module contract \| CE-R01 \| LAB-RESEARCH**

| **ARCHITECTURE STATUS** Research interface only; requires qualified laboratory controls and independent validation. |
|---------------------------------------------------------------------------------------------------------------------|

# 1 Purpose and boundary

Provides the software boundary between Genesis and separately qualified neuronal/astrocytic cultures or organoids. It follows the existing C/O/S/H/L/E architecture and makes no claim that a living module is a general mind.

# 2 Inputs

- Approved MEA/optical observations, sensor calibration and hardware timebase

- Qualified stimulation profile identifiers and independent permit decisions

- Frozen encoders/decoders and experiment identities

# 3 Outputs / Winds

- Typed living-response features and provenance-rich WindEvents

- Interface competence and timing results, not assumed semantic knowledge

- Disconnect and fault records; release-gate assessments

# 4 Required behavior

- Keep physical care independent from learning outcome and rewards.

- Use independently measured limits and approvals from qualified laboratory.

- Preserve separate source identities for Core, Observer and Support communities.

- Treat every living learning claim as an independent experiment with controls.

# 5 Processing and activation

> **1.** Commission and test cell-free interfaces first.
>
> **2.** Qualification controls establish reliable recorded versus artifact signals.
>
> **3.** Connect generated task symbols through approved codebook abstraction.
>
> **4.** Evaluate delayed retention and bridge contribution against software-only controls.
>
> **5.** Hold/halt only task use when faults arise; approved care continues separately.

# 6 Test and release gate

- No instrument command bypasses laboratory-approved limits.

- Disconnecting one bridge clears cached teacher information in independent tests.

- Observed spikes never automatically report knowledge, feeling or agency.

# 7 Failure and protection

- Device variability dwarfs prototype assumptions.

- Improved software decoder is mistaken for tissue acquisition.

# 8 Open research and engineering questions

- Which qualifying measurements distinguish semantic learning from mere reservoir behavior?

# 9 Data contract and evidence trace

All calls use versioned request/response schemas. A WindEnvelope records source, recipient, trace_id, data type, delivered time, validity, provenance and uncertainty. Actual hardware commands, if any, require a separate approved permit. Performance claims cite evaluator runs with sealed test sets.
