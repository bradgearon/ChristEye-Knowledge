**CE-A16 \| DESIGN • 14 NOV 2026**

Roots Registry, Engram Hypothesis Tracking and Growth Maps

Subsystem engineering contract / digital-first + measured research

| **Purpose**        | Locate validated learned relationships in a functional dependency graph and track which physical observations may contribute to them. |
|--------------------|---------------------------------------------------------------------------------------------------------------------------------------|
| **Release stance** | digital-first + measured research                                                                                                     |
| **Data ownership** | Source-labeled, scope-limited, versioned; no silent biological-state claim.                                                           |

# 01 Responsibilities and boundaries

- Keep four distinct graphs: structure, correlation, intervention-supported influence and task relations

- Record a Root as a task-specific retained relation with access conditions

- Attach candidate physical regions only at the evidence tier actually reached

- Track revisions, pruning history, conditional dependence and protected competencies

Scope boundary: DIGITAL-FIRST; biological claims remain separately qualified. This document provides no physical dosing, feeding, stimulation, cell manufacturing or disease intervention instructions.

# 02 Interface contract

| **Inbound**           | RootCandidate; delayed task result; Wind route receipts; sensor observations                 |
|-----------------------|----------------------------------------------------------------------------------------------|
| **Outbound**          | RootRecord; typed graph edge; causal-study hypothesis; longitudinal dashboard view           |
| **Connected systems** | A02 long term, A06 stability, A24 observer, A09 core, A20 filesystem                         |
| **System of record**  | Immutable event ledger and per-module state/claims registry; raw data stay source-addressed. |

# 03 Operational state machine

Required states in declared order (all transitions create a receipt):

1.  Propose

2.  Attribution

3.  Probe

4.  Confirm

5.  Link

6.  Monitor

7.  Revise

Transition logic: Promote a Root after delayed independent performance; associate episodes and candidate features; measure alternative retrieval and reversible software masking; retain negative results and counterexamples.

# 04 Data, observability and model boundary

Measurements: Retention horizon, access reliability, edge confidence and type, old-task delta, cross-context support, graph lineage completeness.

A module must identify the state owner, event source, observation timestamp, validity flags, schema version, confidence where relevant, and the distinction between proposed and measured behavior.

# 05 Verification and acceptance

- A candidate region cannot be called memory storage from imaging alone

- Physical contact does not imply meaning or causality

- A missing response leaves storage vs access unresolved

Acceptance must be performed on held-out inputs with frozen comparison rules. An unqualified biological preparation cannot inherit a software release result.

# 06 Failure modes and guardrails

- High-dimensional neural drift can scramble naive longitudinal IDs

- Correlated firing reflects common input

- Ablation without power may hide useful routes

# 07 Implementation increments

8.  Implement typed graph and provenance schema

9.  Build skill-diff monitor

10. Simulate branch masking and protected regression

## Exit package

Deliver code/API contracts, deterministic unit tests, a versioned release report, an evidence or risk register, and a machine-readable manifest. Unmeasured biological parameters remain null until externally qualified.
