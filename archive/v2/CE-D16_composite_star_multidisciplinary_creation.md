# 1 Purpose and boundary

Defines a flagship package combining several specialist StarChips into one higher-order creative or scholarly workflow while proving the contribution of each component.

| **Identity field**   | **Contract**                                                                                                   |

| **Module ID**        | CE-D16                                                                                                         |

| **Evidence posture** | D = design choice; H = unverified biological or material claim; demonstrated results require independent tests |

# 2 Inputs

- Composite goal and task milestones

- Qualified specialist manifests and shared context rules

- Resource budget, conflict policy and priority of output criteria

# 3 Outputs / Winds

- Directed workflow across domain StarChips

- Integrated artifact with component-wise provenance

- Ablation and regression report for the composite

# 4 Required behavior

- Use a typed orchestration DAG instead of one all-knowing black box.

- Allow creative modules to propose but not override canonical constraints.

- Merge conflicting results through policy and evidence, not averaging confidence blindly.

- Expose a single user-facing Wind interface while keeping internals inspectable.

# 5 Processing and activation

> **1.** Discover qualified components and load required packs.
>
> **2.** Draft a high-level task plan and allocate specialized steps.
>
> **3.** Run tasks asynchronously with explicit handoffs.
>
> **4.** Evaluate global invariants and request bounded revisions.
>
> **5.** Deliver integrated artifact and provenance.

# 6 Test and release gate

- World generation, combat, art and score can run independently and recombine.

- The finished product passes shared constraints, not only individual module tests.

- A missing optional chip yields documented reduced mode.

# 7 Failure and protection

- Composed generators produce mutually inconsistent assets.

- One expert repeatedly revises another's output without convergence.

# 8 Open research and engineering questions

- Which discipline combinations offer measurable gains over one large model?

# 9 Data contract and evidence trace

All calls use versioned request/response schemas. A WindEnvelope records source, recipient, trace_id, data type, delivered time, validity, provenance and uncertainty. Actual hardware commands, if any, require a separate approved permit. Performance claims cite evaluator runs with sealed test sets.
