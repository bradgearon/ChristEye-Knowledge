**CE-A09 \| DESIGN • 14 NOV 2026**

Main Living Network: Soil, Spirit, Heart and Tree

Subsystem engineering contract / hybrid research architecture

| **Purpose**        | Define the core computing substrate as a qualified living Soil with identifiable Spirit participants, response-forming Heart, linked Mesh and demonstrable capabilities. |
|--------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Release stance** | hybrid research architecture                                                                                                                                             |
| **Data ownership** | Source-labeled, scope-limited, versioned; no silent biological-state claim.                                                                                              |

# 01 Responsibilities and boundaries

- Separate tissue boundaries from host software boundaries

- Support task-specific input/response codebooks and independent evaluation

- Report neuronal, astrocytic, inhibitory, structural and telemetry components as typed participants

- Join observers and other modules through reversible electronic interfaces first

Scope boundary: RESEARCH-ONLY. No culture production, growth, stimulation, nutrient dosing, peptide synthesis, ingestion, pathogen modification or medical treatment protocol is authorized.

# 02 Interface contract

| **Inbound**           | Qualified stimulus profile identifiers; task context; sensor observations; care status       |
|-----------------------|----------------------------------------------------------------------------------------------|
| **Outbound**          | Measured neural response; decoded Wind; trial receipt; Root evidence                         |
| **Connected systems** | A11 WindBus, A12 Lotus, A24 observer, A17 support, A22 limit controller                      |
| **System of record**  | Immutable event ledger and per-module state/claims registry; raw data stay source-addressed. |

# 03 Operational state machine

Required states in declared order (all transitions create a receipt):

1.  Source Release

2.  Characterize

3.  Interface Ready

4.  Train

5.  Rest

6.  Evaluate

7.  Review

Transition logic: Host H presents only authorized task events and records delivered events; neural activity remains a physical observation; decoder outputs a class or UNKNOWN; evaluator E scores after response closure and controls feedback disclosure.

# 04 Data, observability and model boundary

Measurements: Macro recall, availability, channel validity, network drift, delayed retention, route contribution, calibration.

A module must identify the state owner, event source, observation timestamp, validity flags, schema version, confidence where relevant, and the distinction between proposed and measured behavior.

# 05 Verification and acceptance

- Valid input/output responses beyond artifacts

- Learning beyond matched noncontingent controls

- A claimed biology-driven result survives frozen digital readout tests

Acceptance must be performed on held-out inputs with frozen comparison rules. An unqualified biological preparation cannot inherit a software release result.

# 06 Failure modes and guardrails

- Organoid is not a validated full mind

- Spinal cells and cerebral organoids are different preparations

- Morphology does not establish task understanding

# 07 Implementation increments

8.  Create software simulator matching device contracts

9.  Build read-only MEA adapter interface

10. Define independent evidence gates before living research

## Exit package

Deliver code/API contracts, deterministic unit tests, a versioned release report, an evidence or risk register, and a machine-readable manifest. Unmeasured biological parameters remain null until externally qualified.
